# Mihon Runner integration boundary

`MihonRunner` adapts the verified JSON bridge contract to `AidokuRunner.Runner`. It is not registered with SourceManager, linked to OpenJDK, or exposed as an installable provider. Configuration is supplied by a future trusted package loader; the adapter does not authenticate the JAR itself. Its expected package digest binds image contexts to a package revision but is not a substitute for package verification.

## Transport

`MihonRuntimeTransport.execute(MihonRuntimeRequest)` is an asynchronous typed command boundary returning the bridge's bounded JSON envelope. Commands flatten to the existing `ExtensionBridge.execute(String)` fields: `extensionPath`, exact string `sourceId`, string `preferences`, `operation`, and operation-specific query/page/manga/chapter records. Requests retain the extension's original manga/chapter URL keys. The first operation verifies runtime discovery against the expected package, version, source ID and language.

`MihonRuntimeTransport.imageData(MihonRuntimeImageRequest)` is separate and returns typed bytes, media type, and optional reported length/digest. A JNI implementation should prefer a direct `byte[]` result to avoid base64 expansion. The request is also Encodable to the existing image operation with `includeData:true` for a reference transport. A transport must propagate runtime failures and cancellation rather than converting them into empty success. Cancellation checks before and after calls prevent late results being published; these checks do not themselves interrupt a synchronous JVM invocation.

`MihonJSONRuntimeTransport` supplies this typed boundary through injected asynchronous String-to-String metadata and String-to-raw-payload image executors. It serializes the actual flat bridge requests, bounds requests at 1 MiB/524288 UTF-16 units and responses at 8 MiB/4194304 UTF-16 units, preserves executor errors, and checks cancellation before and after callbacks. `PackageIdentity` optionally adds `packageSHA256`, `packageName`, `versionName` and `extensionLibrary` to every command, and rejects a changed extension path. Real package wiring must supply this reviewed identity; the native bridge checks the actual local bytes and manifest before loading extension classes. An unbound transport remains useful for the isolated reference fixtures and is not package authorization.

The current proof bridge supports string preferences and a measured Komga dependency set. The adapter exposes no dynamic filters, settings, popular/latest listings, translation discovery, or reader-direction hints that the frozen bridge does not supply. A source-wide `all`/`multi` language becomes no per-chapter language, not a fabricated translation. Status, real upload dates, original chapter order and exact source identities are mapped independently of reader presentation.

## Required lazy image-loader hook

The existing Runner API returns URLRequests or already-decoded page images. It has no asynchronous raw-image provider. `PageInterceptorProcessor` runs after the URL fetch, so using it to call the extension image service would duplicate fetching and bypass request hooks.

Instead, `getPageList` returns page metadata with deterministic internal `honbako-mihon-page://runtime/...` identifiers and bounded contexts. It never loads chapter images eagerly. The URL/context must have been issued by this runner and must match the package/source/preferences scope. Generic URLRequest loading is deliberately unavailable: these internal URLs fail closed in an older loader and cannot fall back to a direct provider request.

The shared `MihonRuntimeImageLoader` detects `MihonRuntimeImageProviding` and now connects these paths, without installing or registering a source:

- Paged and webtoon readers create Nuke `ImageRequest(id:data:processors:...)` using an async closure that calls `runtimeImageData(url:context:)`. Ordinary app crop/downsample/upscale processors remain; the extension's image service is not applied a second time.
- Offline page downloads call the same provider directly and preserve its bytes and image file type. They never send the opaque URL to URLSession or bypass the extension via `Page.imageUrl`.
- Scrub thumbnails and reader/next-chapter preloading already call `ReaderPageView.imageRequest`, so they inherit this lazy boundary and cache identity with the source/context intact.
- `MihonRuntimeCoverImageProviding` and `MihonRuntimeCoverImageLoader` provide a separate lazy cover path. `SourceImageView` and `SumiCoverArtworkLoader` use async Nuke requests whose cache identity includes the package/source/language/preferences scope. Warming and visible search/library tiles share the original bytes. Runtime covers skip ordinary cover URLRequest modification and CoverInterceptorProcessor; unavailable runtime providers fail rather than issuing raw HTTP. Local cover files and ordinary sources retain their existing paths.

The helper rejects opaque pages without a matching source/provider/context, and rejects raw remote URLs for runtime-provider pages rather than falling back to HTTP. Downloaded local files retain their existing local path. Nuke unit tests use an in-memory data/image cache and a network trap to verify transformed preview requests reuse provider bytes with zero ordinary data-loader calls; a webtoon node accepts an injected pipeline so its real load path can be tested without replacing the global app pipeline. The offline test runs an actual DownloadTask and checks two distinct JPEG files and their original byte order.

An image page can have no `imageUrl`: some extensions must resolve it from the page URL. The typed image request preserves that absence. The updated bridge resolves it with the actual HttpSource image-URL hook before invoking its image service. Fetching the HTML page URL as if it were the image is never a valid fallback. Cover commands instead use `operation:"cover",url:"..."` and the selected HttpSource's own headers and HTTP client. They do not invent page context or reuse page-image requests for cover URLs.

Metadata JSON is capped at 8 MiB, individual images at 32 MiB, and page lists at 4096 records. Reported image byte counts and SHA-256 values are checked; malformed responses, changed manga identity, duplicate chapter keys, unsafe URL keys and source mismatches fail rather than changing existing reading state. The typed byte result is still decoded by the normal image loader; mock transport tests establish wire/mapping behavior, not actual extension execution or successful bitmap decoding. The separate host/native proof remains necessary.
